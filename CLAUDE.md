# implementeren-ai-site: repo guide for Claude

Astro site for Implementeren.ai (https://implementeren.ai) on Cloudflare Pages. The company was
called ClaudeZakelijk until October 2026; the old domain claudezakelijk.nl 301-redirects to
implementeren.ai. Branch `main` auto-deploys (~60-90s) via the GitHub Actions workflow
`.github/workflows/deploy.yml`, whose deploy job runs in the `production` environment (only
`main` may use it); that is the only production deploy path.
If a merge does not go live, check the Actions run (`gh run list`) before anything else.

## How changes go live

Nobody pushes to `main`. Every change is a branch plus a pull request, and `main` only accepts a
merge after 2 approvals, at least one of them from a code owner who is not the author (repository
ruleset plus `.github/CODEOWNERS`, which lists Max and Camiel). A PR from Max needs Camiel and one
from Camiel needs Max. Camiel is the face of the site, so nothing reaches it without one of the two signing off. Open the PR, let Cloudflare build the preview,
and post the preview link in the PR so the reviewers can look at the real page.

Break-glass, for a production regression only (the live site is broken or losing data) while the
required reviewers cannot approve in time. An org admin adds a temporary bypass to ruleset
`25944613` ("main: reviewed PRs only"), merges, and removes the bypass straight away:

```bash
R=implementeren-ai/implementeren-ai-site
gh api -X PUT repos/$R/rulesets/25944613 --input <(echo '{"bypass_actors":[{"actor_id":1,"actor_type":"OrganizationAdmin","bypass_mode":"always"}]}')
gh pr merge <nr> -R $R --squash --admin --delete-branch
gh api -X PUT repos/$R/rulesets/25944613 --input <(echo '{"bypass_actors":[]}')
gh api repos/$R/rulesets/25944613 --jq .bypass_actors   # must print []
```

The PR still goes through the normal flow (branch, build, preview link), and gets a comment saying
why it skipped review. Never use this for ordinary content or design changes. First use: PR #5 on
2026-10-28, restoring the Cloudflare Web Analytics beacon while Camiel and Sweder had not yet
joined the org.

## Adding a page

1. Create the page under `src/pages/` wrapping `BasisLayout`
   (`import BasisLayout from '../layouts/BasisLayout.astro'`, pass `titel`, `beschrijving`, `pad`).
2. Add its route to `src/data/public-pages.json`. `scripts/check-pages.mjs` fails the build for any
   route that is not listed there.
3. If it should be indexed by Google, it must also fall under the `zakelijk` allowlist in
   `src/data/indexering.mjs`. Everything outside that list gets noindex automatically.
4. `npm run build` must pass clean (`check-pages`, `astro build`, `check-dist`).

`functions/_indexering.json` and `functions/_redirects.json` are generated by
`scripts/gen-edge.mjs`; never hand-edit them. Redirects go in `public/_redirects`.

## Content rules the build enforces

`scripts/check-dist.mjs` fails the build on: e-mail addresses other than @implementeren.ai
(and the old @claudezakelijk.nl during the transition), the
names of people other than Camiel, the names Proxuma or Dxfferent, placeholders or HTML comments
on indexable pages, and a page H1 inside `.reveal-target`. `scripts/quality-gate.py --all` checks
published content and runs in the deploy workflow before the build.

## House styling tokens (Tailwind v4, from `src/styles/global.css`)

Surfaces `bg-papier` / `bg-white` · text `text-inkt` / `text-inkt-zacht` · accent terracotta
`text-accent-diep` (use `-diep` for AA contrast) · teal for the one primary CTA only `bg-teal` ·
borders `border-lijn` · fonts `font-serif` (headings) / `font-sans` (body) · containers
`mx-auto max-w-3xl px-5 py-16 md:py-24` · cards `card-shadow rounded-xl border border-lijn
bg-white p-5` · section header rule: class `sectie-lijn` on an `<h2>` · long prose:
`class="prose prose-stone max-w-none"`. Do not invent new colors. Content language follows the
topic (Dutch or English). No em dashes, no AI-slop phrasing.
